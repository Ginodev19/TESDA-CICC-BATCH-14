What Is the Largest int?

You do not have to know this for the exam, but the maximum number an int can hold is 2,147,483,647. How do we know this? One way is to have Java tell us:
JavaSystem.out.println(Integer.MAX_VALUE);

The other way is with math. An int is 32 bits, $2^{32}$ is 4,294,967,296. Divide that by 2 and you get 2,147,483,648. Then subtract 1 as we did with bytes and you get 2,147,483,647.

It's easier to just ask Java to print the value, isn't it?

Reference Types

A reference type refers to an object (an instance of a class).

References do not hold the value of the object they refer to.

A reference "points" to an object by storing the memory address where the object is located.

Java
java.util.Date today;
String greeting;
The today variable is a reference of type Date and can only point to a Date object.

The greeting variable is a reference that can only point to a String object.

Destroying Objects

Java provides a garbage collector to automatically look for objects that aren't needed anymore.

All Java objects are stored in your program memory's heap.

The heap, which is also referred to as the free store, represents a large pool of unused memory allocated to your Java application.

If your program keeps instantiating objects and leaving them on the heap, it will run out of memory.


Garbage Collection   

Refers to the process of automatically freeing memory on the heap by deleting objects that are no longer reachable in your program. There are many different algorithms for garbage collection.   

Java provides a method called System.gc() — It meekly suggests that now might be a good time for Java to kick off a garbage collection run. Java is free to ignore the request.

An object is no longer reachable when one of two situations occurs:

The object no longer has any references pointing to it.

All references to the object have gone out of scope.


Objects vs. References

A Reference:

Has a name.

A reference may or may not be created on the heap.

All references are the same size no matter what their data type is, and are accessed via their variable name.



The Heap / An Object:

Objects are always on the heap.

They have no name and can only be accessed via a reference.

Objects vary in size depending on their class definition.

Garbage Collection Example

Garbage collection (GC) is Java's automatic process for reclaiming heap memory from objects that are no longer reachable.

You don't normally need to manually delete objects.

1. Creating an Object
Student student = new Student();

Conceptually:

student ─────────> Student object
                    (on the heap)

The object is reachable because student refers to it.

2. The Object Becomes Unreachable

Now suppose:

student = null;

Conceptually:

student ─────> null

Student object
     ↑
     no reference

The Student object is now unreachable.

It becomes eligible for garbage collection.

Eligible does not mean Java immediately deletes it.

The JVM decides when garbage collection actually happens.


new Student()
     ↓
Object created
     ↓
Reference points to object
     ↓
Reference becomes null
     ↓
Object may become unreachable
     ↓
Eligible for garbage collection
     ↓
JVM may reclaim its memory

Why is this useful?

Without garbage collection, your program would have to manually find and delete objects that are no longer needed.

Java handles this automatically.

This helps:

♻️ Reuse memory for new objects
🧹 Remove objects that are no longer needed
💾 Prevent unnecessary memory consumption
🛡️ Reduce certain types of memory-management errors
